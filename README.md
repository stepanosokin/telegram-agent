# Telegram Agent

Локальный получатель сообщений для тестового Telegram-бота. Подключается к сессиям Codex CLI/TUI на общем App Server. Исходящие уведомления по-прежнему отправляет установленный навык через свои команды `Send`/`Status` на Windows и `send`/`status` на Linux.

## Ручной запуск

1. Подготовьте отдельного тестового бота и откройте личный чат с ним.
2. В домашнем каталоге пользователя вне Git создайте каталог `~/.telegram`, если его ещё нет. В четыре отдельных текстовых файла запишите токен бота (`.bot_token`), ID бота (`.bot_id`), ID владельца (`.owner_user_id`) и ID личного чата (`.chat_id`). Если рабочие уведомления уже используют этот профиль, запустите получатель на отдельном тестовом профиле ОС с Codex и тестовым ботом.
3. Установите права каталога `0700` и файлов `0600` на Linux. На Windows проверьте ACL каталога и каждого файла, включая унаследованные записи. Доступ можно дать владельцу, локальной группе администраторов и SYSTEM. Получатель проверяет права до обращения к Telegram. Команда `icacls "$HOME\.telegram" /T` покажет ACL без вывода содержимого файлов.
4. Откройте сессию Codex CLI/TUI на общем App Server и возьмите идентификатор сессии из `/status`. Для новой сессии сначала отправьте одно сообщение в Codex, чтобы появилась история для подписки. Нужна версия App Server с `thread/queue/add` и `thread/queue/start`. При запуске из очереди сервер проверяет, что сессия свободна. На Windows команда `codex` должна находить нативный `codex.exe` в PATH.
5. Из корня проекта выполните с Node.js 22 или новее:

   ```text
   node src/receiver.mjs start <идентификатор-сессии-Codex> [ещё-идентификатор]
   ```

Получатель отправляет новые полные сообщения агента. Ответьте на такое сообщение через «Ответить» в Telegram. Привязки действуют до остановки через Ctrl+C. При неподтверждённой доставке проверьте историю и очередь сессии на компьютере перед повтором. При конфликте получателей Telegram процесс завершится с сообщением об ошибке.

## Локальные проверки

Запустите `npm test` (или `node --test "test/*.test.mjs"`). Тесты запускают штатный получатель отдельным процессом, используют временный профиль с вымышленными значениями и подставляют публичные API Telegram и Codex. Сеть и рабочие учётные данные не нужны.
