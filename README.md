# Telegram Agent

Локальный получатель сообщений для тестового Telegram-бота. Подключается к сессиям Codex CLI/TUI на общем App Server и к сессиям OpenCode 2 на общем локальном сервере. Исходящие уведомления по-прежнему отправляет установленный навык через свои команды `Send`/`Status` на Windows и `send`/`status` на Linux.

## Ручной запуск

1. Подготовьте отдельного тестового бота и откройте личный чат с ним.
2. В домашнем каталоге пользователя вне Git создайте каталог `~/.telegram`, если его ещё нет. В четыре отдельных текстовых файла запишите токен бота (`.bot_token`), ID бота (`.bot_id`), ID владельца (`.owner_user_id`) и ID личного чата (`.chat_id`). Если рабочие уведомления уже используют этот профиль, запустите получатель на отдельном тестовом профиле ОС с Codex и тестовым ботом.
3. Установите права каталога `0700` и файлов `0600` на Linux. На Windows проверьте ACL каталога и каждого файла, включая унаследованные записи. Доступ можно дать владельцу, локальной группе администраторов и SYSTEM. Получатель проверяет права до обращения к Telegram. Команда `icacls "$HOME\.telegram" /T` покажет ACL без вывода содержимого файлов.
4. Для Codex откройте сессию CLI/TUI на общем App Server и возьмите идентификатор сессии из `/status`. Для новой сессии сначала отправьте одно сообщение в Codex, чтобы появилась история для подписки. Нужна версия App Server с `thread/queue/add` и `thread/queue/start`. При запуске из очереди сервер проверяет, что сессия свободна. На Windows команда `codex` должна находить нативный `codex.exe` в PATH.
5. Для OpenCode 2 откройте диалог в Desktop или TUI, подключённом к общему локальному серверу. Передайте его идентификатор `ses_…` с префиксом `opencode:`. Получатель находит сервер через штатную регистрацию OpenCode.
6. Из корня проекта выполните с Node.js 22 или новее:

   ```text
   npm ci
   node src/receiver.mjs start <идентификатор-сессии-Codex|opencode:ses_…> [ещё-идентификатор]
   ```

Получатель отправляет новые полные сообщения агента. Ответьте на такое сообщение через «Ответить» в Telegram, чтобы продолжить исходный диалог. Для каждого нового текста бот показывает свой список сессий. После запуска сессия появляется в списке, когда от неё приходит новое сообщение агента. Получатель также может показать OpenCode после проверки активного хода или открытия диалога на общем сервере. Сверьте название сессии и окончание её ID, затем нажмите кнопку. Если исходная привязка ответа недоступна, бот сообщит об этом и предложит выбрать из доступных сессий.

Когда Codex задаёт вопрос с вариантами, бот показывает вопрос и кнопки в сообщении с названием сессии. Для нескольких вопросов выберите по варианту для каждого. Секретные вопросы и запросы разрешения MCP из этого интерфейса остаются в Codex. App Server сообщает о закрытии запроса. При одновременном ответе с компьютера принятый вариант можно проверить в исходной сессии.

В формах OpenCode выберите варианты для каждого вопроса, затем нажмите «Отправить ответ». Отмеченный вариант можно снять повторным нажатием. OpenCode проверяет и принимает полный ответ, после чего бот показывает принятые варианты и убирает кнопки. Для произвольного ввода, условных полей и внешних действий используйте исходную сессию.

Для команды Codex бот показывает рабочий каталог, причину (если её передал App Server) и только те кнопки разового разрешения или отклонения, которые указал App Server. Запросы расширения доступа, изменения правил и запросы, чей контекст нельзя целиком и однозначно показать, требуют ответа в Codex. При обрыве после отправки решения проверьте его результат в исходной сессии.

Запросы разрешений OpenCode отображаются в Telegram без кнопок: решение принимается в исходной сессии. Кнопки можно добавить, только если [публичный API](https://opencode.ai/docs/api#tag-permission) гарантирует, что решение применяется к тому же открытому экземпляру запроса, который видел владелец. В контракте OpenCode 2.3.2 такой гарантии нет. Отдельная сверка через GET не заменяет серверную гарантию.

Получатель хранит ID сообщений, привязки к сессиям и технические статусы отправки в закрытом каталоге `receiver-text-v1-*` внутри `~/.telegram`. Содержимое сообщений и ожидающие выбора тексты в журнале не сохраняются. После перезапуска ответ на прежнее сообщение требует заново подтвердить сессию. Для Codex дождитесь живого события исходного диалога. Для OpenCode получатель сверяет текущий сервер и сессию. После смены сервера откройте исходный диалог на компьютере.

При статусе «Ответ не доставлен» повторите текст новым сообщением. При неизвестном результате проверьте историю и очередь исходной сессии перед повтором. Если получатель остановился во время отправки, повторное обновление Telegram показывает известный статус без новой передачи. При конфликте получателей Telegram процесс завершится с сообщением об ошибке.

## Локальные проверки

После `npm ci` запустите `npm test`. Тесты запускают штатный получатель отдельным процессом, используют временный профиль с вымышленными значениями и подставляют публичные API Telegram, Codex и OpenCode. Для запуска самих тестов сеть и рабочие учётные данные не нужны.

Для ручной приёмки OpenCode используйте чистые сессии и отдельный тестовый бот и чат. Повторите обмен отдельно в Desktop и TUI: отправьте запрос из открытого диалога, найдите новый ответ с меткой `OpenCode` и названием сессии в чате, затем отправьте отличимый текст через «Ответить». Проверьте его в истории исходного диалога по ID, а не только по названию. Проверка с локальной подстановкой Telegram не подтверждает доставку в живой чат.

Если ход выполняется на изолированном сервере, продолжайте на компьютере. Для повторной проверки откройте исходный диалог на общем сервере. Список активных ходов OpenCode и отправка ответа — отдельные операции: публичный `prompt` не принимает предусловие об ожидаемом владельце хода.

Для проверки форм откройте чистую сессию на отдельном тестовом сервере OpenCode. Через [публичный API форм](https://opencode.ai/docs/api#tag-session) создайте одну форму до запуска получателя и ещё одну после запуска. Используйте два вопроса: один с готовыми вариантами и один с множественным выбором. Отправьте полный ответ кнопками и проверьте сохранённый ответ по ID сессии и формы, показ принятых вариантов и снятие кнопок. Повторите с другой формой: выберите вариант, отмените форму из второго клиента и убедитесь, что отправка больше недоступна. В отчёте отдельно укажите, использовался ли выделенный Telegram-бот или подстановка API.

Для приёмки разрешений используйте установленный App Server Codex и OpenCode 2.3.2 с отдельными временными профилями. Путь к временному `CODEX_HOME` должен быть коротким из-за системного предела длины пути к Unix-сокету. В штатном получателе подставьте только API Telegram. В Codex запросите разрешение на безвредную команду `echo`, сверьте контекст и доступные кнопки, отправьте разовый ответ через подставное обновление Telegram и проверьте закрытие запроса в App Server. В OpenCode запросите чтение временного файла через публичный API и убедитесь, что сообщение содержит действие и путь. Отклоните запрос в исходной сессии, затем создайте запрос на другой временный файл с тем же ID. Для обоих запросов должны появиться отдельные уведомления без кнопок.
